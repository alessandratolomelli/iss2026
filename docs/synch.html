FireflySync

Introduction

Goal: Costruire un sistema costituito da 3 lucciole, che si devono sincronizzare dopo 10 secondi.

Requirements

R1  Simulare il comportamento di tre lucciole attraverso la definizione di un modello qak.

R2  Inizialmente le lucciole lampeggiano ciascuna con una frequenza costante propria.

R3 Dopo 10 secondi le tre lucciole devono essere sicnronizzate e lampeggiare alla stessa frequenza.

Requirement analysis

Di quante entità ho bisogno? Sicuramente tre: una per ogni lucciola. Queste ultime vengono modellate come attori poichè indipendenti. Un esempio di attore è il seguente: 
 
QActor firefly1 context ctxfirefly {
    [#
       var X = 10
       var Y = 10
    #]
    State s0 initial {
        println("$name | X=$X Y=$Y") color magenta
    }
    Goto wait_sync

    State wait_sync {
        println("$name | aspetto sync...") color magenta
    }
    Transition t0
        whenEvent sync -> flash

    State flash {
        forward griddisplay -m cellstate : cellstate($X,$Y,1)
        delay 500
        forward griddisplay -m cellstate : cellstate($X,$Y,0)
    }
    Goto wait_sync
}
Il requisito R3 pone il problema della sincronizzazione, le opzioni potrebbero essere:
  • un orchestratore o lucciola regina che dopo 10 secondi comunica alle altre le frequenza da utilizzare,
  • un orchestratore o lucciola regina che dopo 10 secondi emette degli impulsi con una propria frequenza,
  • dopo 10 secondi le lucciole commutano su una sequenza concordata,
  • dopo 10 secondi le lucciole modificano la loro frequenza sulla base di quella dei vicini

Problem analysis

Dopo una valutazione delle possibili soluzioni, è stata scelta l'opzione 2, che prevede l'introduzione di un orchestratore centrale modellato come attore. Questa scelta è motivata da:
  • semplicità implementativa: la sincronizzazione è ottenuta tramite un unico punto di controllo;
  • chiarezza del comportamento: tutte le lucciole reagiscono allo stesso evento globale;
  • riduzione della complessità: non è necessario gestire interazioni tra le lucciole.
L'orchestratore (coordinator) emette periodicamente un evento di tipo "sync", che rappresenta un impulso di sincronizzazione globale. Le lucciole sono modellate come attori reattivi che:
  • attendono l'evento di sincronizzazione;
  • al ricevimento dell'evento, eseguono il lampeggio (flash);
  • notificano il proprio stato a un attore esterno (griddisplay).
Questa soluzione realizza una sincronizzazione centralizzata, in cui il comportamento globale è determinato dall'orchestratore.
